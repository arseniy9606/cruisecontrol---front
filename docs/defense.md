## Порядок показа

1. Отключить backend, БД и S3. Запустить `npm ci`, `npm run dev`. Открыть http://localhost:3000/fuel_consumptions и Network: показать плитку, локальные ресурсы, отсутствие запросов к API (скриншот 1).
2. Открыть карточку, показать ленту и Network. Кнопкой «Следующий автомобиль» сменить карточку без нового Document-запроса (скриншот 2).
3. В плитке показать «Автомобиль без медиа» с изображением по умолчанию; поля image_url и video_url этой записи пустые (скриншот 3).
4. Открыть http://localhost:3000/fuel_consumptions/feed/5: показать DefaultVideo.mp4 и локальные пути по умолчанию (скриншот 4).
5. Показать ConsumptionFilter.tsx: тип Props, value, onApply, состояние draft, Form onSubmit, preventDefault и проверку границ (скриншот 5).
6. Показать App.tsx: range/useState, отбор по consumption_rate, props automobiles/range/onApply. Проверить 8–13 → внедорожник, микроавтобус и карточка без медиа; 90–100 → пустой список; сброс → 5 карточек (скриншот 6).
7. Показать useState в App, фильтре, FuelImage и ленте. Объяснить отдельное состояние редактируемого и применённого диапазона, раскрытия описания и ошибки медиа (скриншот 7).
8. Показать useEffect, useParams и useNavigate в FuelFeedPage и useLocation в TabBar: ID из URL, переход к следующему, сброс описания, заголовок вкладки и cleanup. В StrictMode эффекты в разработке дополнительно проверяются повторным запуском (скриншот 8).
9. Показать README: две страницы, кнопки, поля, меню, запуск и ветка (скриншот 9).

## Контрольные вопросы

**React.** Библиотека построения интерфейсов из компонентов. React согласует дерево элементов и обновляет нужные части DOM при изменении состояния.

**Props и состояние.** Props передаются родителем и доступны ребёнку для чтения. State принадлежит компоненту; setter useState планирует новый рендер. В App хранится применённый диапазон, в ConsumptionFilter — редактируемый. Функция onApply передаётся через props вверх как обратный вызов.

**Компонент и элемент.** Компонент — функция, например FuelConsumptionCard. Элемент — результат JSX, описывающий нужный интерфейс, например `<FuelConsumptionCard automobile={item} />`. Элемент не изменяют; при новом рендере создаётся новое описание.

**useState.** Возвращает значение состояния и setter. Объект не меняют напрямую; создают новый. Компонент фильтра использует `{ ...draft, minimum: value }`.

**useEffect.** Синхронизирует компонент с внешней средой после рендера. В ленте меняет document.title и сбрасывает локальное состояние при изменении автомобиля; cleanup восстанавливает заголовок. Массив зависимостей задаёт, когда эффект повторяется.

**Жизненный цикл.** Монтирование, обновление, размонтирование. Функция компонента вычисляет JSX; эффект выполняется после применения изменений, cleanup — перед повторным эффектом и при размонтировании. Хуки вызываются на верхнем уровне до условных return.

**Vite.** Среда разработки с быстрым обновлением модулей HMR и сборщик оптимизированных статических файлов. TypeScript отдельно проверяется командой tsc, Vite сам по себе типы не проверяет.

**Babel.** Преобразователь JavaScript/JSX с системой плагинов. Конкретный движок преобразования зависит от версии Vite/plugin-react; наличие Babel не требуется для бизнес-логики компонентов.

**Роутинг.** BrowserRouter хранит навигацию в истории браузера, Routes выбирает компонент по URL. Link/NavLink/useNavigate позволяют перейти без перезагрузки документа. useParams извлекает ID автомобиля. useLocation возвращает текущий путь для подсветки пункта меню.

**Redux и Context.** Не используются в ЛР5 по заданию. Состояние поднимается в App и передаётся через props. Лекция 10 описывает последующий этап с общей моделью состояния и авторизацией.

**Mock и CORS.** Mock — типизированная коллекция в src/modules/mock.ts. HTTP-запросов к backend нет, CORS для этой лабораторной не требуется. Браузер отдельно загружает локальные файлы frontend.
